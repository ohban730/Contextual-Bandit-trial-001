# embeddings.py の説明書

## ひとことでいうと
動画のタイトル(ことば)を、コンピュータが「意味の近さ」を計算できる
**たくさんの数字の並び(ベクトル)**に変換する係です。

## なにをしているところ？

「ねこの可愛い動画」と「猫ちゃんまとめ」は、人間が読めば
「似た内容だな」とすぐわかりますよね。でもコンピュータにとって、
文字はただの記号の並びで、「似ている」を直接くらべることができません。

そこでAI(人工知能)の力を借ります。文章を渡すと、その**意味**を表す
数字の並び(たとえば384個の数字のリストなど)を返してくれる
「翻訳機」のようなモデルを使います。この数字の並びのことを
**埋め込みベクトル(embedding)**と呼びます。

意味が似ている文章どうしは、この数字の並びも「似た並び」になります。
なので、あとで`semantic.py`が「この2つの数字の並びはどれくらい
似ているか」を計算することで、「意味が近いタイトルかどうか」を
判定できるようになります。

## 出てくる主な道具

### `SentenceTransformer(MODEL_NAME, device=device)`
`sentence_transformers`という、文章を埋め込みベクトルに変換するための
AIモデルを読みこむ道具です。`paraphrase-multilingual-MiniLM-L12-v2`という
名前のモデルは、日本語を含むたくさんの言語に対応しています。

### `device = "cuda" if torch.cuda.is_available() else "cpu"`
パソコンに、計算が速くなる特別な部品(GPU、ここでは`"cuda"`)が
あればそれを使い、なければ通常の頭脳(`"cpu"`)を使う、という
切り替えです。

### `_get_model()`
AIモデルは読みこむのに時間がかかるので、**一度だけ**読みこんで、
`_model`という共有の場所に保存しておき、次回からはそれを
使い回す仕組みです(`global _model`)。

### キャッシュ(`_load_cache` / `_save_cache`)
一度ベクトルに変換した動画タイトルは、`video_embeddings.npz`という
ファイルに保存しておきます。同じ動画をまた変換する無駄を防ぎます。
`enrich.py`のキャッシュと考え方は同じです。

### `embed_video_titles(video_id_to_title, use_cache, batch_size)`
メインの関数です。まだベクトル化していない動画だけをモデルに渡し、
`batch_size`件ずつまとめて(256件など)効率よく変換します。

## 具体的な流れの例

1. `{"vid001": "ねこの可愛い動画", "vid002": "猫ちゃんまとめ"}` が渡される
2. まだキャッシュに無い2件をモデルに渡す
3. モデルが `[0.12, -0.05, 0.33, ...]` のような数字の並びを
   それぞれの動画に対して返す
4. キャッシュに保存し、`video_id`と`embedding`(数字の並び)の表を返す

意味が近い2つのタイトルなら、返ってくる数字の並びも
「近い場所を指す矢印」のようになります。

## もっと知りたい人へ
- `normalize_embeddings=True`: ベクトルの「長さ」を1にそろえる設定です。
  こうしておくと、あとで「向き(意味)の近さ」だけを純粋に
  比べやすくなります。
- `np.savez_compressed`: 複数のnumpy配列を、1つの圧縮ファイルとして
  まとめて保存する道具です。
