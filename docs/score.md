# score.py の説明書

## ひとことでいうと
それぞれのチャンネルについて、これまで計算してきたいろいろな点数
(久しぶり度・好きだった度・ジャンルの一致度・意味の近さ)を
**1つの総合点**にまとめる係です。

## なにをしているところ？

学校のテストで、国語・算数・理科・社会の点数から「合計点」や
「平均点」を出すことがありますよね。このファイルがやっているのも
それとよく似ています。ただし、教科によって「配点の重み」が
違う場合があります(`config.py`の`ScoringWeights`で決められています)。

## 出てくる主な道具

### `_normalize(series)`
点数の「ものさし」を、みんな0〜1の範囲にそろえる係です。
たとえば「視聴回数」は1回〜100回までバラバラな数字ですが、
これを一番多い人を1.0、一番少ない人を0.0になるように
引き伸ばしたり縮めたりします。

こうしておかないと、「視聴回数(1〜100)」と
「ジャンルの一致度(0〜1)」のように、そもそもの数字の
大きさがぜんぜん違う項目を、公平に足し算できません。

もし全員が同じ点数(最大と最小が同じ)だったら、
差がつけられないので、みんな仲良く0.5にしています。

### `score_channels(channel_df, weights, now)`
メインの関数です。次の順番で計算します。

1. `days_since_last_watch`: 「最後に見てから何日たったか」を計算
2. `recency_score`: その日数を0〜1に正規化(日数が多いほど高得点
   =「久しぶり度」が高い)
3. `frequency_score`: 視聴回数を0〜1に正規化(「好きだった度」)
4. もし`genre_score`や`semantic_score`の列がすでにあれば、それも
   足し合わせる対象に加える
5. それぞれの点数に「重み」を掛けて合計し、使った重みの合計で割る
   (これが**加重平均**です)

### なぜ「使った重みの合計で割る」のか
`enrich.py`や`semantic.py`を実行しない設定(`--no-enrich`や
`--no-semantic`)で動かした場合、`genre_score`や`semantic_score`の
列自体が存在しません。そのときは、存在する項目の重みだけを
合計して割ることで、「使わなかった項目のせいで点数が不当に
低くなる」ことを防いでいます。

## 具体的な流れの例

重みが `recency=0.4, frequency=0.2` だけが有効(genre/semanticは無し)
だとして、あるチャンネルの `recency_score=0.8`, `frequency_score=0.5`
だったとします。

```
weighted_sum = 0.4 * 0.8 + 0.2 * 0.5 = 0.32 + 0.10 = 0.42
active_weight = 0.4 + 0.2 = 0.6
score = 0.42 / 0.6 = 0.7
```

このチャンネルの総合点は 0.7 になります。

## もっと知りたい人へ
- `sort_values("score", ascending=False)`: 総合点が高い順に
  並べかえます。
- `reset_index(drop=True)`: 並べかえたあとの行番号を、
  0番からきれいに振り直します。
